# 已知限制（如实记录）

> 本文档刻意写得具体，避免"看起来什么都能做"的误导。
> 每一条都标注了**现象**、**原因**与**可能的改进方向**。

---

## 一、x86-64 解码器不是完整实现

### 1.1 支持范围（当前）

**前缀**

| 类别 | 支持的字节 |
|------|-----------|
| LOCK | `F0` |
| REP/REPNE | `F2` / `F3` |
| 段前缀 | `2E` `36` `3E` `26` `64` `65` |
| 操作数大小 | `66` |
| 地址大小 | `67` |
| REX | `40`–`4F`（W/R/X/B 全解析） |

**控制流指令（CFG 的核心，全部支持）**

| 指令 | 编码 |
|------|------|
| 短条件跳转 Jcc（16 种条件） | `70`–`7F` rel8 |
| 近条件跳转 Jcc（16 种条件） | `0F 80`–`0F 8F` rel32 |
| 无条件跳转 JMP | `EB` rel8 / `E9` rel32 |
| 函数调用 CALL | `E8` rel32 |
| 返回 RET | `C3` / `C2` imm16 |
| 停机 HLT | `F4`（`0F 0B` ud2 亦按终止处理） |
| 循环 LOOP / LOOPE / LOOPNE | `E2` / `E1` / `E0` rel8 |
| JRCXZ | `E3` rel8 |
| 间接 CALL | `FF /2` |
| 间接 JMP | `FF /4` |

**数据传送与运算**

`mov`（88/89/8A/8B/C6/C7/B0-BF）、`lea`（8D）、`movzx`/`movsx`（0F B6/B7/BE/BF）、
`movsxd`（63）、`push`/`pop`（50-5F/68/6A/8F/FF6）、
`add`/`or`/`adc`/`sbb`/`and`/`sub`/`xor`/`cmp`（00-3D 全系列 + 80/81/83 分组）、
`test`（84/85/A8/A9/F6F7-0,1）、`not`/`neg`/`mul`/`imul`/`div`/`idiv`（F6/F7 分组）、
`inc`/`dec`（FE/FF 分组）、移位（C0/C1/D0-D3 分组）、
`xchg`（86/87）、`cmpxchg`/`xadd`（0F B0/B1/C0/C1）、
`nop`（90、0F 1F）、`leave`（C9）、`cwde`/`cdq`（98/99）、
`cmovcc`（0F 40-4F）、`setcc`（0F 90-9F）、`bswap`（0F C8-CF）、
`syscall`（0F 05）、`cpuid`（0F A2）、`rdtsc`（0F 31）、
标志位操作（F5/F8-FD）。

### 1.2 **不支持**的指令（遇到即报错并停止）

| 类别 | 例子 | 后果 |
|------|------|------|
| 三字节 opcode | `0F 38 xx`、`0F 3A xx`（SSSE3/SSE4/AES 等） | 报 `三字节 opcode 尚未支持` |
| SSE / AVX 浮点与向量 | `movss`、`movaps`、`pxor`、`vzeroupper` | 报 `不支持的 opcode` |
| x87 浮点 | `fld`、`fstp` | 同上 |
| 字符串操作 | `rep movsb`、`stos` | 前缀已解析，但 `A4/A5/AA/AB` 等 opcode 未收录 |
| 系统指令 | `wrmsr`、`invlpg` 等（`0F 01` 分组） | `0F 01` 有表项，但 `0F 30+` 未收录 |
| 位操作 | `bt`、`bsf`、`bsr`、`popcnt`、`lzcnt` | 未收录 |

**遇到不支持指令的行为**：
`decode()` 返回 false，`InstructionStream` **立即停止**该函数的解码，
输出 `解码停止于 0x... ：不支持的 opcode XX`，已解码的部分仍然保留。
**绝不把未知指令假定为 1 字节继续解码** —— 那会让后续全部错位。

### 1.3 改进方向

按"实际遇到的 opcode"逐步补表即可，无需改动解码框架：
在 `X86OpcodeTable.cpp` 中增加表项，必要时在 `X86Decoder.cpp` 的
`buildOperands()` 中补充该指令的操作数格式。

## 二、间接跳转 / 间接调用无法解析目标

**现象**：`jmp *%rax`、`call *0x1234(%rip)`、`jmp *(%rax,%rbx,8)`
这类指令，`Instruction::targetKnown` 被置为 `false`，
CFG 中生成一条 `EDGE_INDIRECT` 边，目标块为 `NULL`。

**原因**：目标值在运行时才确定，静态分析需要数据流/值集分析。

**影响**：CFG 在间接跳转处"断开"，可达性分析会漏掉经由该边到达的块。

**改进方向**：对 `jmp *(%rip+disp)` 形式的跳转表可做启发式识别；
更严格的做法是值集分析（value-set analysis）。

## 三、switch 跳转表（jump table）

GCC 对分支较多的 `switch` 会生成**跳转表**：

```
jmp *0x4040(,%rax,8)       ; 间接跳转，目标在只读数据段
```

本实现能**识别出这是一条间接跳转**（`FF /4`），但：

- 不会去读取跳转表的内容；
- 因此不会为每个 `case` 生成一条 `EDGE_BRANCH_TRUE` 边；
- 这些 `case` 对应的基本块会被 `ReachabilityPass` 判为**不可达**。

**这在 `switch_test()` 上可以直接观察到**：`--text` 输出里会出现灰色的
不可达块，它们实际上都是可达的。

**改进方向**：识别 `jmp *table(,reg,scale)` 模式，从只读节读取跳转表，
为每个表项生成一条边（同时做表项合法性校验，防止把数据当代码）。

## 四、"向后跳转边"是演示性近似，不是严格 back edge

**当前判据**：边的目标块地址 ≤ 源块地址。

**严格定义**：边 (u, v) 是 back edge，当且仅当 **v 支配 u**
（从入口到 u 的所有路径都必须经过 v）。

**差别**：

- 可能**误报**：两个相邻循环之间往回的跳转、编译器重排后地址较小的
  顺序跳转，都可能被标成"向后"；
- 可能**漏报**：结构复杂时，回边不一定指向更低的地址。

**在 demo 中**：`classify` 的 `B7 -> B6` 这一条确实对应源码的 `for` 循环
（已人工核对）。但这属于"本例中恰好正确"，不是普遍保证。

**代码与文档的措辞约定**：一律使用 **backward jump hint（向后跳转提示）**，
不使用 "back edge" 这一术语指代它。

**改进方向**：实现支配树（Lengauer–Tarjan 或简单的迭代数据流算法），
用 `v dominates u` 作为判据。

## 五、依赖符号表，strip 后无法按名字定位函数

**现象**：被 `strip` 过的二进制没有 `.symtab`，只有 `.dynsym`
（且只含动态导出符号）。本实现先查 `.symtab`，再查 `.dynsym`；
两者都查不到时输出：

```
[elfcfg] ERROR: 在 xxx 中找不到函数 'yyy'
[elfcfg] ERROR: 提示：可用 --symbols 查看该文件包含哪些函数
```

**影响**：无法分析大多数系统程序（如 `/bin/ls`）。

**改进方向**：函数边界识别（function identification）：
按 `.eh_frame` 的 FDE 记录、或按 `push %rbp; mov %rsp,%rbp` 特征扫描。

## 六、其他限制

| 限制 | 说明 |
|------|------|
| 只支持 ELF64 小端 x86-64 | ELF32 / 大端 / 其他架构直接报错退出 |
| 只分析单个函数内部 CFG | 不跨函数；`call` 在块尾时生成 `EDGE_CALL` 边指向下一块，但不进入被调函数 |
| `st_size == 0` 的符号 | 用"同节内下一个函数符号地址"或"节末尾"兜底推算长度，会输出 DEBUG 日志 |
| 不解析 `.eh_frame` / 异常表 | 无法处理 C++ 异常展开表；对 C 程序无影响 |
| 不处理重定位 | 分析的是链接后的可执行文件；`.o` 目标文件中的重定位项不会被应用 |
| 不识别函数序言/尾声模式 | 不据此推断栈帧大小（留给 `StackAnalysis` 扩展） |
| DOT 输出不合并重复边 | 若条件跳转的两条边指向同一块，会输出两条平行边（语义上确实是两条不同路径） |

## 七、验证方式与可信度

**指令边界与助记符**：用 `tests/verify_against_objdump.py` 与 GNU objdump
逐条比对（**仅开发期使用，程序本身不调用 objdump**）：

```
classify: 26/26 条指令 地址+助记符+操作数 全部一致
main    : 26/26 条指令 全部一致
```

**CFG 结构**：与早期 objdump 版本生成的 DOT 逐边比对：

```
B0->B2 jle | B0->B1 fall | B1->B5 jmp | B2->B4 jle | B2->B3 fall |
B3->B5 jmp | B4->B5 fall | B5->B7 jmp | B6->B7 fall | B7->B6 jle | B7->B8 fall
—— 边的连接关系与标签完全一致
```

**未经验证的部分**：本文档列出的所有"不支持"项，均未做系统性测试，
只是按表项覆盖范围推断。补充 opcode 后需要重新交叉验证。
